# Work 이미지 업로드

이 스킬의 목표는 원본 이미지와 약 400KB의 축소 이미지를 Azure Storage에 함께
업로드하는 것이다. 현재 작업 중인 이 저장소의 루트에서
`scripts/upload-to-azure-storage.cs`를 실행한다. 절대 경로를 스킬에 하드코딩하지
않는다.

## 입력 선택

원본 이미지는 대화에 첨부하거나, 환경에서 제공하는 파일 선택기를 통해 받는다. 이미지가
없으면 경로를 직접 타이핑해 달라고 요구하지 말고, 작가님에게 파일을 첨부하거나 파일
선택기로 고르게 한다. 파일명을 추측하거나 Downloads 폴더에서 임의로 고르지 않는다.

작품 기간을 이미지 상위 폴더명에서 확실히 알 수 있을 때만 자동으로 사용한다. 그 외에는
환경에서 제공하는 **선택형 질문 UI**로 기간을 묻는다. 자유 입력 질문으로 바꾸지 않는다.
선택지가 세 개를 넘지 않도록 아래처럼 두 단계로 나눈다.

1. 먼저 `2006–2014`, `2015–2022`, `2023–2026` 중 기간대를 선택하게 한다.
2. `2006–2014`를 고르면 `2006–2010` 또는 `2011–2014`를 한 번 더 고르게 한 후, 해당
   범위의 두 기간(`2006-2008`/`2008-2010` 또는 `2011-2012`/`2013-2014`) 중 하나를
   고르게 한다.
3. `2015–2022`를 고르면 `2015–2018` 또는 `2019–2022`를 한 번 더 고르게 한 후, 해당
   범위의 두 기간(`2015-2016`/`2017-2018` 또는 `2019-2020`/`2021-2022`) 중 하나를
   고르게 한다.
4. `2023–2026`을 고르면 `2023-2024`, `2025-2026` 중 하나를 고르게 한다.

업로드 방식도 선택형 질문으로 확인한다.

- `실제 업로드` — 원본과 축소본을 Azure에 올린다. 이 선택은 해당 파일 한 건의 업로드
  권한으로 간주한다.
- `미리 확인` — 축소본만 만들고 업로드하지 않는다.

기존 파일을 바꿔야 하는 요청이 명확하지 않으면 덮어쓰지 않는다. 사용자가 기존 같은
이름의 원본·축소본을 교체한다고 명시한 경우에만 선택형 질문으로 `기존 파일 유지`와
`기존 파일 교체` 중 고르게 하고, 후자를 선택했을 때만 `--overwrite`를 사용한다.

## 실행 절차

1. 저장소의 `AGENTS.md`를 읽고, 작업 트리 상태를 확인한 후 안전한 경우
   `origin/main`을 fetch하고 `git pull --ff-only origin main`을 수행한다. `main` 이외의
   브랜치를 만들거나 전환하지 않는다.
2. 실제 업로드를 선택했다면 저장소 루트의 `azure-connection-string.txt`가 존재하는지만
   확인한다. 파일 내용은 읽거나 표시하거나 채팅으로 요청하지 않는다. 파일이 없거나 비어
   있으면 업로드를 멈추고, 작가님이 로컬 파일에 연결 문자열을 한 줄로 넣도록 안내한다.
   이 파일은 `.gitignore`에 등록되어 있으므로 Git에 추가하거나 커밋하지 않는다.
3. 저장소 루트에서 먼저 아래와 같이 dry-run을 실행해 축소 크기와 Azure Blob 경로를
   확인한다.

   ```sh
   dotnet run --file scripts/upload-to-azure-storage.cs -- "<원본 이미지 경로>" --period <YYYY-YYYY> --dry-run
   ```

4. 실제 업로드를 선택한 경우에만 동일한 명령에서 `--dry-run`을 빼고 실행한다. 교체가
   선택된 경우에만 끝에 `--overwrite`를 추가한다. 스크립트가 출력한 원본·축소본 URL을
   확인하고 결과로 알린다.
5. 업로드된 이미지를 페이지에 연결하는 일은 별도 요청이 있을 때만 한다. 요청되면 Work
   페이지의 마크업 수정, 로컬 Jekyll 확인, commit·push까지 `AGENTS.md` 절차를 따른다.

## 안전 기준

- Azure 연결 문자열을 명령행 인자, 코드, Git, 로그, 채팅에 넣지 않는다.
- 실패·취소·동일 이름 충돌이 발생하면 결과를 설명하고, `--overwrite` 재시도는 작가님의
  선택 후에만 한다.
- Azure 또는 GitHub 계정 권한·인증 문제를 저장소 안에서 해결할 수 없으면 개발자 전경원님께
  부담 없이 편하게 연락하도록 안내한다.
